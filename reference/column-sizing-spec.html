Specification: mixed column sizing ​

Contract ​

  • CS-01: Each leaf column supports meta.sizingMode: "pixel" | "percentage". The default is pixel. Mode is independent of native enableResizing.
  • CS-02: Pixel widths use native size, columnSizing, minSize, and maxSize. Resizing an ordinary pixel column changes only its own pixel state.
  • CS-03: Percentage columns divide container width after pixel widths are subtracted, proportionally to finite non-negative weights; at least one percentage weight must be positive. The default weight is one.
  • CS-04: Percentage drag updates relative weights, never stores those weights as pixel state, and preserves proportional scaling after container resizing.
  • CS-05: Minimum and maximum constraints remain pixels for every mode. Redistribute constrained shares. Overflow horizontally at combined minimums; leave space unused when combined maximums prevent filling.
  • CS-06: Disabled columns have no handles and cannot be resize partners. Disabled percentage columns still respond to container-space changes.
  • CS-07: Percentage transfers use the nearest enabled percentage peer, favoring the following column on ties. Without one, use the nearest enabled pixel column. No partner means no misleading handle.
  • CS-08: An all-pixel table uses its last resizable column as flexible fallback. pixelFallback="widest" instead selects the largest current pixel size, favoring the last on ties. Fixed columns cannot be fallback targets.
  • CS-09: When no all-pixel fallback is eligible, keep fixed widths and allow unused space or horizontal overflow. A fallback's own bounds still apply.
  • CS-10: Native columnResizeDirection controls both layout direction and pointer/keyboard deltas. RTL and LTR must grow toward logical inline-end.
  • CS-11: Respect native table/column resize permission and native commit mode. Default onEnd previews without committing; release commits both state maps. onChange commits during movement. Keyboard actions commit immediately.
  • CS-12: Expose controlled columnWeights and onColumnWeightsChange; require the callback when weights are controlled. Use native controlled pixel state.
  • CS-13: Invalid modes, weights, constraints, or container widths fail explicitly. Do not mask errors with success-shaped defaults.
  • CS-14: Align header/body widths, preserve sorting, stable row identity, virtualization, Gantt observations, and application-independent packaging.
  • CS-15: Standalone and application table implementations must remain equivalent.

Input and accessibility ​

  • CS-16: Focusable vertical separators expose a single-column accessible name and actual rendered width through aria-valuenow.
  • CS-17: Arrow keys move by 2px, Shift+Arrow by 10px. Home requests the lower bound; End requests the viewport-limited upper bound. Apply both partner constraints. Do not produce infinite CSS widths.
  • CS-18: Capture the primary pointer. Finish on release, cancel, or capture loss. Cancel the snapshot on container resizing.
  • CS-19: Cancellation discards uncommitted onEnd previews; already committed onChange values remain.

Acceptance examples ​

  1. In a 1000px container, two 100px pixel columns plus weights 1:3 render 100, 100, 200, 600. At 1400px, render 100, 100, 300, 900.
  2. With one 100px pixel and two equal percentage columns, render 100, 450, 450. Growing the first percentage column by 90px produces 100, 540, 360; at 1600px, render 100, 900, 600.
  3. Growing an enabled pixel column does not resize an adjacent ordinary pixel column. Percentage space or the all-pixel fallback absorbs the difference.
  4. A disabled pixel neighbor never changes during direct percentage resizing; the nearest enabled partner is used instead.
  5. If all pixel columns are disabled, growing the container does not grow any column. No resize handles exist.
  6. If only one percentage column exists and no enabled pixel partner exists, it still scales with its container, but has no handle.
  7. Dragging RTL left by 40px has the same logical effect as dragging LTR right by 40px. RTL ArrowLeft and LTR ArrowRight have matching effects.
  8. A 160px minimum Gantt column remains at least 160px; chart/header widths remain aligned after resizing and sorting.
  9. onEnd produces no sizing callback during preview and commits on release. onChange produces callbacks during movement.

Validation ​

Run npm test, npm run lint, npm run build, and npm run docs:build in the standalone package. Run application table/schedule typechecks and the design-system component tests. Validate real pointer/keyboard interaction, container resizing, RTL, and Gantt alignment in a browser.

Non-goals ​

No percentage-of-entire-table mode, automatic persistence, new dependencies, column pinning, grouped-column resize interaction, or change to Gantt internals. Native size getters remain pixel-state getters rather than renderer layout measurements. The existing public resizeColumnPair utility remains compatible.
