Row virtualization ​

Virtualization is opt-in. Pass virtualize to ResizableTable when rendering a large row model would otherwise create too many DOM rows:

tsx
<ResizableTable table={table} label="All vehicles" virtualize />

Without this prop, all rows in the current table row model are rendered. Virtualization only limits rendered rows; it does not paginate or fetch data, and the full input data remains in memory.

Renderer behavior ​

  • The scroll container created by ResizableTable is the virtualizer's scroll element.
  • The initial row-size estimate is 36 pixels, with an overscan of two rows. Rendered rows are measured and their sizes are observed.
  • The header height is measured and used as the virtual scroll margin.
  • The active focused table row is retained in the rendered range when it moves outside the normal virtual range.
  • The table exposes row counts and row indexes when virtualization is active.

Use the renderer's scroll container as the scrolling region. In a flex layout, give the containing region a constrained height and allow it to shrink (commonly with min-height: 0) so the container can scroll. Row content can vary in height; the virtualizer measures rows after rendering, but highly variable content may require additional layout testing.

Virtualization is not a substitute for application-level pagination or server-side data loading. Choose the point at which to enable it based on the consumer's data and performance measurements; the package does not impose a row-count threshold.
