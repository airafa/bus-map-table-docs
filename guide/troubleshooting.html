Troubleshooting ​

@busmap/table returns a registry 404 ​

The current package README targets a configured Verdaccio registry, and @busmap/table@0.1.1 is not available from the public npm registry at the time of writing. Configure the @busmap scope for the registry that hosts the package, or build and install a local tarball as described in Getting started.

React peer dependency warning or hook errors ​

Prefer the latest stable React release, keeping React DOM and compatible type packages aligned across workspaces. This release declares the exact peer react@19.3.1, matching the current Bus Map application. For newer React versions, validate compatibility and use a table release whose peer declaration supports that version. A recommendation to upgrade does not override an exact peer constraint; do not suppress the warning.

The table is unstyled ​

Import @busmap/table/style.css from the application entry. Confirm that the bundler processes CSS from dependencies and that the stylesheet subpath is preserved in the installed package. The package does not automatically import the consumer's design-system theme.

The sorting select has no useful options or throws ​

The selector includes only leaf columns that TanStack reports as sortable. The sort-control hook throws if a sortable column has a non-string header. Provide text headers and enable sorting on the intended columns. A Cannot sort column error indicates that a selected/stored column ID is not a sortable column in the current table.

A resize separator does not move the expected column ​

Pixel handles update their own width. Percentage handles transfer space against the nearest enabled percentage peer, or an enabled pixel partner when no percentage peer exists. Disabled columns are skipped. Check native enableResizing, enableColumnResizing, columnResizeDirection, pixel bounds, and the sizing-mode guide. Native defaults are 20px minimum and Number.MAX_SAFE_INTEGER maximum. In all-pixel tables, the last resizable column is the fallback; use an explicit percentage column for stable expansion.

A single percentage column already owns all remaining space. Without an enabled partner, no handle is shown. enableResizing: false on a percentage column disables interaction, not proportional expansion; use pixel mode for fixed width.

A virtualized table has no useful scroll area ​

ResizableTable owns the scroll element. Constrain its available height in the consuming layout; flex parents commonly need min-height: 0. Verify that the virtualized view is inside the intended scrolling region and that the browser provides ResizeObserver.

A theme value appears ignored ​

Set supported --table-* properties on the renderer's scroll container or an ancestor. Column width, column minimum width, and virtual position/height variables are calculated by the renderer; do not override those internal properties. Check the CSS custom property reference.

A row doesn't activate with the keyboard ​

getRowProps forwards attributes and handlers; it does not implement keyboard activation. Use a native button/link in the cell or provide and test the complete interaction in the consuming module.

@lego/graphs tags render empty in the table ​

Register the required Graph constructors with customElements.define once before the table view mounts. For the range-only example, the required tags are lego-gantt, lego-gantt-row, and lego-gantt-date-range. The guide draws its grid in CSS, so lego-gantt-column-divider is not required. Check that the view sets date_domain on the Gantt host and data on its row element as properties after mount; they are complex values, not string attributes.

Gantt cells have no range or render at the wrong width ​

Each Gantt row expects data items with a date timestamp or [start, end] timestamp pair and the matching type. Make sure the shared Gantt date_domain covers those timestamps and the cell's custom-element host uses width: 100%. The package's cell itself has overflow clipped, so give the Gantt column enough minimum width for the visualization.

Gantt grid lines drift after sorting, resizing, or scrolling ​

In the inspected @lego/graphs@0.0.1-rc30, each Gantt instance keeps an initial tick anchor from its first time domain. Virtualized rows mount at different times, so internal column dividers can become misaligned between rows and with the header as the live domain advances. Sorting can expose different mounted instances; changing the divider interval alone does not remove the anchor difference.

Remove lego-gantt-column-divider from these cells. Draw a decorative, non-interactive CSS grid over each chart instead, using the same equal interval count as the header axis: four in this guide's example, five in Bus Map. Keep the header and grid at the full chart width without horizontal padding, and continue passing the same live date_domain to every chart. This fix belongs in the consumer integration, not the table package. See the shared-grid example and sorting and resizing checks.

Verify grid boundaries against the header within one pixel after sorting both directions, resizing columns, advancing the clock, and scrolling to newly mounted rows. Also check the date-to-pixel scale, actual shadow-root canvas height, and range/point vertical center; aligned grid lines alone do not prove that the chart content is aligned. Wait for the asynchronous canvas width and scale updates to settle. Use a visible or headless browser: a hidden page can defer resize work and leave newly mounted canvases at zero width.

Many Gantt cells make scrolling slow ​

The Gantt row renderer starts its own canvas loop (60 FPS by default). Table virtualization limits mounted table rows, but every mounted Gantt still runs its own renderer. Reduce the number of simultaneous chart cells, profile the consumer page, or use a simpler static visualization when interaction is not needed. See the Gantt-column guide.
