Accessibility and testing ​

Accessibility behavior in the package ​

  • ResizableTable requires a label, applied as the table's accessible name.
  • TableSortControls renders a labeled select and direction button in a sorting group. Its label defaults to "Sort by"; the group name is "Table sorting".
  • Sorted headers expose aria-sort.
  • Each resize separator has role="separator", a generated label, vertical orientation, current value, and keyboard support. Arrow keys resize by 2 pixels, Shift+Arrow by 10 pixels, and Home/End move to the available bounds.
  • Virtualized tables include row counts and indexes. A focused rendered row is retained while the virtual range changes.
  • Table primitives use native table elements and expose stable data-slot attributes for styling.

Consumer responsibilities ​

  • Provide a meaningful label for every ResizableTable.
  • Use text headers for sortable columns so the sorting selector has useful labels. If custom column header renderers are used, verify the generated separator labels with assistive technology.
  • getRowProps only forwards row attributes and handlers. It does not add keyboard activation or selection behavior. Prefer native interactive controls in cells, or implement and test the complete keyboard interaction when rows themselves are interactive.
  • Set aria-selected only when the row actually represents a selectable selection state. Styling the selected state does not implement selection.
  • Test virtualized tables with the actual assistive technology and browser combinations your product supports. Only rendered rows are present in the DOM at a given scroll position.
  • Check focus visibility, contrast, zoom, narrow viewports, and right-to-left direction in the consuming theme.
  • If a cell contains a canvas-based visualization such as @lego/graphs Gantt, provide an equivalent text label or summary. Canvas graphics do not become meaningful table text automatically. See the Gantt-column guide.

Suggested consumer tests ​

Use the test runner already established by your application; this package doesn't prescribe or ship a test framework.

  1. Render representative rows and assert their values and table accessible name.
  2. Select a sort column, verify the row order, toggle direction, then choose Unsorted.
  3. Focus a resize separator and test Arrow, Shift+Arrow, Home, and End while asserting the target and any partner stay within configured bounds. Verify independent pixel resizing and proportional scaling after a percentage drag.
  4. Test row callbacks and selection attributes in the feature module.
  5. If testing virtualization in a DOM emulator, provide the environment's normal ResizeObserver and geometry support or mock them narrowly; then verify rendered range, row indexes, and focus retention.
  6. Build the production app to verify the stylesheet export and CSS custom properties are included.

Run npm test for pure sizing regressions, including weighted constraints, fixed columns, fallback selection, and post-resize scaling. The exported resizeColumnPair utility can also be tested in a consumer's existing setup. Use a real browser for pointer capture, RTL, commit timing, and chart alignment; see the sizing contract.
