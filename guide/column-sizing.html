Pixel and percentage column sizing ​

Sizing and permission to resize are independent:

meta.sizingModeenableResizingContainer growthDragging
"pixel"falseFixed pixel widthNo handle
"pixel"trueFixed except the all-pixel fallbackUpdates pixel width
"percentage"falseScales with its shareNo handle
"percentage"trueScales with its shareUpdates relative weights

Omitted mode means "pixel"; resizing is enabled by TanStack by default. These settings work in any column order, including a non-final percentage column, multiple percentage columns, and a fixed final column.

Complete mixed example ​

tsx
import {
  createColumnHelper, ResizableTable, resizableTableFeatures, useResizableTable,
} from "@busmap/table";

type Route = {
  bus: string;
  destination: string;
  notes: string;
  timeline: string;
};
const column = createColumnHelper<typeof resizableTableFeatures, Route>();
const columns = column.columns([
  column.accessor("bus", {
    header: "Bus",
    size: 96,
    minSize: 64,
    enableResizing: false,
    meta: { sizingMode: "pixel" },
  }),
  column.accessor("destination", {
    header: "Destination",
    size: 240,
    minSize: 120,
    maxSize: 480,
    enableResizing: true,
    meta: { sizingMode: "pixel" },
  }),
  column.accessor("notes", {
    header: "Notes",
    minSize: 80,
    enableResizing: false,
    meta: { sizingMode: "percentage", weight: 1 },
  }),
  column.accessor("timeline", {
    header: "Timeline",
    minSize: 160,
    enableResizing: true,
    meta: { sizingMode: "percentage", weight: 3 },
  }),
]);

function Schedule({ data }: { data: Route[] }) {
  const table = useResizableTable({
    columns,
    data,
    columnResizeDirection: "rtl",
    columnResizeMode: "onEnd",
  });
  return <ResizableTable table={table} label="Schedule" />;
}

In a 1136px container, the 96px and 240px columns leave 800px. Notes receives 200px and Timeline receives 600px. At 1536px, their widths become 300px and 900px, while the two pixel columns remain 96px and 240px.

RTL and drag direction ​

Set the native table option columnResizeDirection: "rtl"; use "ltr" for left-to-right. The renderer applies that direction to its scroll container, so visual order, logical handle placement, pointer deltas, and arrow keys agree. It does not infer a table option from an ancestor's dir.

In LTR, moving a handle right grows its column. In RTL, moving it left grows the column. Use an inner element with its own direction when cell content needs a different text direction; do not override the table's layout direction independently of columnResizeDirection.

Fixed and resizable pixel columns ​

Use native size, minSize, maxSize, and enableResizing. size initializes the pixel width; native columnSizing[columnId] overrides it after resizing. enableResizing: false removes the handle and excludes that column from resize partner selection and automatic all-pixel fallback selection.

Setting minSize and maxSize to the same value also constrains a width. Prefer the explicit permission flag for a column intended to be non-resizable. Equal-bound columns have no handle and are excluded from partner/fallback selection. For a resizable pixel column that never grows with the container, include at least one explicit percentage column elsewhere.

Percentage means a share of the remainder ​

text
remaining = container width - sum(pixel column widths)
column width = remaining * column weight / sum(percentage column weights)

This is not a percentage of the entire table width. Weights 1:3, 25:75, and 100:300 represent the same ratio. The default weight is 1. Weights must be finite and non-negative, and at least one percentage weight must be positive. size is not a weight; use meta.weight.

Minimums and maximums remain pixels, in both modes. Bound-constrained columns stop growing/shrinking and the other percentage columns share the remainder. If minimums do not fit, the table scrolls horizontally rather than shrinking below those minimums. If every percentage column reaches its maximum, excess container space stays unused.

enableResizing: false does not freeze a percentage column's rendered width: it still responds to available space. Use pixel mode for a fixed width.

What each handle changes ​

  • Pixel: changes that column's stored pixel width independently. Percentage columns absorb the new remaining space. Other ordinary pixel columns do not change.
  • Percentage: transfers width to/from the nearest resizable percentage column, favoring the following column when distances tie. The resulting percentage widths become the new relative weights. They continue scaling after a later container resize.
  • No enabled percentage peer: transfers width against the nearest enabled pixel column. Disabled columns are skipped. This includes the common single Gantt-column case. With no valid partner, the percentage handle is omitted: changing the weight of the only remaining share cannot change its width.
  • Automatic pixel fallback: its handle adjusts the nearest enabled pixel partner inversely. Without a partner, its handle is omitted.

Both sides' pixel constraints clamp a transfer. Percentage columns without resize permission keep their current width during a direct percentage-column transfer, but continue to scale on later container changes.

All-pixel fallback ​

When there are no explicit percentage columns, pixelFallback="last" selects the last resizable pixel column to absorb the container's remaining width. Its size is not its rendered width; it acts as the flexible remainder. This preserves the original schedule layout without requiring metadata.

Use <ResizableTable ... pixelFallback="widest" /> to select the resizable pixel column with the largest current pixel size instead. Ties favor the last column. Selection is recalculated from current sizing state.

Fixed columns are never selected. If all pixel columns are non-resizable, their widths remain fixed, spare space stays empty, and narrow containers scroll. The fallback respects its own minimum/maximum as well.

Prefer an explicit percentage column when the identity of the expanding column should remain stable through subsequent edits.

Native state and controlled weights ​

The implementation uses installed TanStack Table 9.3.1:

  • columnSizingFeature owns pixel state and constraints.
  • columnResizingFeature supplies enableResizing, getCanResize(), enableColumnResizing, columnResizeDirection, and columnResizeMode.
  • columnResizeMode: "onEnd" is the native default: pointer movement previews the layout; pixel and weight changes commit on release. "onChange" commits during movement. Keyboard actions commit immediately.
  • enableColumnResizing: false removes all handles. In an all-pixel table it also prevents fallback selection; explicit percentage columns still scale.

TanStack is headless and its native sizing state is pixel-based. Weighted remaining-space allocation is a renderer extension, not a built-in TanStack percentage option. Native column.getSize(), header.getSize(), and total-size getters do not include renderer-computed percentage/fallback widths. Measure the actual cells when integrating charts; the Gantt host's existing ResizeObserver already does this.

The renderer owns weights internally by default. For persistence or reset, control them separately from TanStack's pixel state:

tsx
const [columnWeights, setColumnWeights] = useState<ColumnWeights>({});
const table = useResizableTable({ columns, data });

return (
  <ResizableTable
    table={table}
    label="Schedule"
    columnWeights={columnWeights}
    onColumnWeightsChange={setColumnWeights}
  />
);

Import useState from React and ColumnWeights from @busmap/table. The callback receives a complete weight map, not an updater function. Supplying columnWeights without its change callback throws an error. Controlled pixel sizing uses TanStack's normal state.columnSizing and onColumnSizingChange options; do not store weights in that pixel map.

To reset both, call table.resetColumnSizing() and set the controlled weight map to {} to restore metadata defaults. The pixel reset alone does not reset weights. A percentage transfer can renormalize every percentage weight; store the complete callback value. The renderer does not persist data externally.

Input and compatibility ​

Separators are focusable and announce the actual rendered pixel width. Arrow keys move by 2px; Shift+Arrow moves by 10px, respecting RTL. Home moves toward the minimum. End moves toward the smaller of the configured maximum and the current viewport/column width, further limited by partner bounds. This avoids requesting an effectively infinite table from TanStack's large default maximum. Pointer capture supports mouse, touch, and pen.

In onEnd mode, pointer cancellation discards the preview. In onChange mode, already committed changes remain. A container resize cancels an active drag so the next interaction starts with fresh measurements.

Migration changes: pixel columns no longer transfer width to the immediately adjacent ordinary pixel column. Handles belong to individual enabled columns, including the final column when it has a resize partner. Separator labels are Resize <header> column; update tests that used the old pair labels. Existing all-pixel tables retain last-resizable-column container expansion. Pixel constraints use TanStack's defaults (currently 150 initial, 20 minimum, and Number.MAX_SAFE_INTEGER maximum) unless overridden.

The Bus Map schedule explicitly marks Bus, Route, and Stops as pixel columns and Timeline as percentage mode with weight 1. The chart implementation does not need a sizing API change.
