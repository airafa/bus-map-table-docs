Render a @lego/graphs Gantt in a table column ​

This guide composes @busmap/table with the Gantt custom elements exported by @lego/graphs. It renders one compact Gantt chart in a schedule column for each table row. The table package does not depend on, register, or adapt @lego/graphs; the consuming application owns all graph integration.

What belongs where ​

ConcernOwner
Fetching schedule data, joining it to entities, permissions, and converting domain records into graph rangesApplication data/domain layer or feature module
Choosing the time domain, visible rows, row labels, and which actions are availableFeature module
Mapping a typed ScheduleRow to the Gantt column and handling UI eventsConsumer view/component
Table rendering, column sizing, sorting, and optional table-row virtualization@busmap/table
Gantt chart rendering and drawing its ranges/ticks@lego/graphs

Do not add @lego/graphs, schedule models, application state, or domain rules to the @busmap/table package.

Compatibility and dependencies ​

The package inspected for this guide is @lego/graphs@0.0.1-rc30. Its package.json exports Gantt constructors from the @lego/graphs root; the repository README's installation example uses the singular name @lego/graph, which does not match that package name. Use the actual package name and the version available from your organization's registry.

The Gantt is a set of Web Components, not a React component. Import the constructors and register their tag names once in the application bootstrap, before the feature module renders. This is a browser-only operation.

ts
// app/src/registerGraphs.ts
import {
  DataRange,
  Gantt,
  GanttRow,
} from "@lego/graphs";

const ganttElements = [
  ["lego-gantt", Gantt],
  ["lego-gantt-row", GanttRow],
  ["lego-gantt-date-range", DataRange],
] as const;

for (const [tagName, constructor] of ganttElements) {
  if (!customElements.get(tagName)) {
    customElements.define(tagName, constructor);
  }
}

Import that registration module once from the browser app entry, before rendering modules. Avoid having every feature module call customElements.define; the registry is global and registering a tag twice throws. If a Gantt feature also uses points or interactions, register those additional constructors too: DataPoint, CircleElement, MouseEvents, and MouseEventsSetAction.

Add the dependencies at the layer that owns the view. In a Yarn workspace, do dependency changes from the workspace root. For example, a feature module could use @busmap/table as a dependency and declare @lego/graphs as a peer when the application shell provides it:

json
{
  "dependencies": {
    "@busmap/table": "0.1.1"
  },
  "peerDependencies": {
    "@lego/graphs": "0.0.1-rc30"
  }
}

Use the versions and dependency placement defined by the consumer's actual release and deployment model, rather than copying these example numbers blindly. Prefer the latest stable React release, with matching React DOM and compatible types. The current @busmap/table release requires exact peer react@19.3.1, matching the current Bus Map application. Newer React versions require compatibility validation and a table release with a matching peer declaration. @lego/graphs does not declare a React peer; it provides custom elements.

Define a consumer-owned row projection ​

Prepare data in the application before it reaches the table. @lego/graphs expects range items with numeric millisecond timestamps and type: "range"; its Gantt row also supports point items. A table view can use a narrow projection such as:

ts
export type GanttRange = {
  id: string;
  type: "range";
  date: [number, number];
  color: string;
};

export type ScheduleRow = {
  id: string;
  route: string;
  destination: string;
  ranges: GanttRange[];
  scheduleSummary: string;
};

Keep conversion from a domain model to ranges in an application selector, view-model function, or module boundary. For example, map each trip's start and end instants to [startMs, endMs]; validate the domain data there. The table and Gantt guide does not prescribe a route or trip model.

All Gantt cells in one column should use the same [Date, Date] time domain so bars can be compared horizontally. Each range's date values should be within that domain and in start-to-end order.

For a live table, draw a decorative grid in the consumer using the same fractions as the header axis. In the inspected Gantt version, internal dividers use a per-instance initial tick anchor. Virtualized rows mount at different times, so those dividers can drift between rows as the domain advances, even when every chart receives the same current domain. See grid-line drift troubleshooting for symptoms, the consumer-side fix, and verification steps.

Add a typed display column ​

The example below includes ranges and a shared four-interval grid. It uses refs to set the Gantt's complex properties after the custom elements mount. This avoids depending on React's treatment of array-valued properties as HTML attributes.

tsx
import { useEffect, useMemo, useRef, type RefCallback } from "react";
import {
  createColumnHelper,
  ResizableTable,
  TableSortControls,
  resizableTableFeatures,
  useResizableTable,
} from "@busmap/table";

const GANTT_ROW_HEIGHT = 44;
const column = createColumnHelper<typeof resizableTableFeatures, ScheduleRow>();

type GanttElement = HTMLElement & {
  date_domain: [Date, Date];
};

type GanttRowElement = HTMLElement & {
  data: GanttRange[];
};

type GanttRangeElement = HTMLElement & {
  width: (item: GanttRange) => number;
  stroke_width: (item: GanttRange) => number;
  stroke_color: (item: GanttRange) => string;
  fill_color: (item: GanttRange) => string;
};

function GanttCell({
  ranges,
  domain,
  summary,
}: {
  ranges: GanttRange[];
  domain: [Date, Date];
  summary: string;
}) {
  const ganttRef = useRef<GanttElement>(null);
  const rowRef = useRef<GanttRowElement>(null);

  useEffect(() => {
    if (!ganttRef.current || !rowRef.current) return;
    ganttRef.current.date_domain = domain;
    rowRef.current.data = ranges;
  }, [domain, ranges]);

  const configureRange: RefCallback<GanttRangeElement> = element => {
    if (!element) return;
    element.width = () => 12;
    element.stroke_width = () => 0;
    element.stroke_color = range => range.color;
    element.fill_color = range => range.color;
  };

  return (
    <div className="gantt-cell" role="img" aria-label={summary}>
      <lego-gantt ref={ganttRef} aria-hidden="true" className="gantt-cell__chart">
        <lego-gantt-row ref={rowRef} height={GANTT_ROW_HEIGHT}>
          <lego-gantt-date-range ref={configureRange} />
        </lego-gantt-row>
      </lego-gantt>
      <span className="gantt-cell__grid" aria-hidden="true">
        {[0, 1, 2, 3].map(index => <span key={index} />)}
      </span>
    </div>
  );
}

export function ScheduleTable({
  rows,
  domain,
}: {
  rows: ScheduleRow[];
  domain: [Date, Date];
}) {
  const columns = useMemo(
    () => column.columns([
      column.accessor("route", {
        header: "Route",
        size: 120,
        minSize: 88,
      }),
      column.accessor("destination", {
        header: "Destination",
        size: 180,
        minSize: 120,
      }),
      column.display({
        id: "schedule",
        header: "Schedule",
        size: 360,
        minSize: 260,
        maxSize: 720,
        cell: ({ row }) => (
          <GanttCell
            ranges={row.original.ranges}
            domain={domain}
            summary={row.original.scheduleSummary}
          />
        ),
      }),
    ]),
    [domain],
  );

  const table = useResizableTable({
    columns,
    data: rows,
    getRowId: schedule => schedule.id,
  });

  return (
    <>
      <TableSortControls table={table} label="Sort schedules by" />
      <ResizableTable
        table={table}
        label="Route schedules"
        virtualize
        style={{ "--table-row-height": `${GANTT_ROW_HEIGHT}px` }}
        renderHeaderExtra={header =>
          header.column.id === "schedule" ? (
            <ScheduleAxis domain={domain} />
          ) : null
        }
      />
    </>
  );
}

ScheduleAxis is application-owned header content. A simple implementation can render evenly spaced labels for the same domain:

tsx
function ScheduleAxis({ domain }: { domain: [Date, Date] }) {
  const formatter = new Intl.DateTimeFormat(undefined, {
    hour: "2-digit",
    minute: "2-digit",
  });
  const ticks = [0, 0.25, 0.5, 0.75, 1].map(fraction =>
    new Date(domain[0].getTime() +
      (domain[1].getTime() - domain[0].getTime()) * fraction)
  );

  return (
    <div className="schedule-axis" aria-hidden="true">
      {ticks.map(tick => (
        <span key={tick.getTime()}>{formatter.format(tick)}</span>
      ))}
    </div>
  );
}

renderHeaderExtra is part of ResizableTable and places the returned content below the header label; a truthy value marks that header for the renderer's taller timeline-header layout. It does not configure or control the Gantt's own time scale. The app must keep ScheduleAxis's domain in sync with the GanttElement.date_domain.

Add consumer styles so the custom element fills the resizable cell:

css
.gantt-cell {
  position: relative;
  display: block;
  width: 100%;
  min-width: 0;
  height: var(--table-row-height);
}

.gantt-cell__chart {
  display: block;
  width: 100%;
  height: 100%;
}

.gantt-cell__grid {
  position: absolute;
  inset: 0;
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  pointer-events: none;
}

.gantt-cell__grid > span {
  border-inline-end: var(--border-width-default) solid var(--table-row-border);
}

.schedule-axis {
  display: flex;
  width: 100%;
  justify-content: space-between;
  font-size: 0.75rem;
  font-weight: 400;
}

The table renderer sets each cell's width and transfers widths as the user resizes the schedule column. The Gantt's resize observer reads its host width, so keep the host at width: 100% and avoid a fixed pixel width inside the column.

The internal lego-gantt-row also needs an explicit numeric height at mount: its default is 47px, and changing host CSS alone does not resize its canvas. In this example GANTT_ROW_HEIGHT is shared with the table's row height. When a theme or responsive layout can change that height, observe the chart host with ResizeObserver, store the measured height in state, and pass it as both height and key on lego-gantt-row. Remounting the internal row recreates its canvas with the new size. Disconnect the observer on unmount.

Range and point elements center themselves at half the internal canvas height by default. If supplying y_position, derive it from the measured height rather than a compact-control token or a fixed 24px chart height. Verify the actual shadow-root canvas and drawing center, not only the host's CSS height. Account for the cell's bottom border when comparing vertical bounds; it is not padding.

TypeScript declarations for custom elements ​

The inspected @lego/graphs package does not declare a types entry. If your TypeScript application reports missing declarations or unknown JSX tags, add a small app-owned declaration file (for example app/src/types/lego-graphs.d.ts) for the elements used by that app. Keep this shim in the consumer; do not make @busmap/table depend on Graph types.

ts
import type { DetailedHTMLProps, HTMLAttributes } from "react";

declare module "@lego/graphs" {
  export const DataRange: CustomElementConstructor;
  export const Gantt: CustomElementConstructor;
  export const GanttRow: CustomElementConstructor;
}

declare module "react" {
  namespace JSX {
    interface IntrinsicElements {
      "lego-gantt": DetailedHTMLProps<HTMLAttributes<HTMLElement>, HTMLElement>;
      "lego-gantt-row": DetailedHTMLProps<HTMLAttributes<HTMLElement>, HTMLElement> & {
        height?: number;
      };
      "lego-gantt-date-range": DetailedHTMLProps<
        HTMLAttributes<HTMLElement>,
        HTMLElement
      >;
    }
  }
}

If the app already declares @lego/graphs, extend that declaration instead of defining the same module twice. Add further JSX element declarations for the Gantt subcomponents that the view actually uses.

Data updates, virtualization, and performance ​

  • Pass stable row IDs to getRowId; resizing and sorting can reorder rows, and Gantt instances hold internal drawing state.
  • Keep row data and the shared date domain stable when unchanged. The example updates the custom element properties when ranges or domain change.
  • virtualize is enabled above because each visible row mounts a Gantt and canvas. Table virtualization limits how many rows are mounted at once, but does not make an individual Gantt cheaper.
  • @lego/graphs Gantt rows start a rendering loop using the chart's fps property, which defaults to 60. Several visible charts can consume significant rendering time. Profile the real page; consider a simpler static visualization if the column does not need Gantt interaction or rendering behavior.
  • ResizableTable virtualizes table rows, not Gantt content. Its estimated height is 36px before measurement; set the table row CSS property and Gantt row height consistently, and verify measured scrolling in the target browser.
  • Do not put an entire multi-route Gantt chart in every row cell. This pattern is one compact Gantt (and one Gantt row) per table row. If the desired visualization is one shared multi-row Gantt aligned with separate table labels, compose a single chart alongside the table at the application level instead; @busmap/table does not synchronize two independent scrollers.

Sorting and resizing ​

For fixed versus expanding columns, weighted shares, resize permissions, and RTL, see Pixel and percentage column sizing. Mark the Gantt column with meta: { sizingMode: "percentage", weight: 1 } to keep it expanding regardless of its position; use pixel mode for non-expanding neighboring columns.

The schedule column above is a TanStack display column and is not included in the package's sortable-column selector. The route and destination accessors remain sortable with the package's client-side sorting feature. If users need to sort by a schedule value, expose that value as a separate accessor or add a consumer-owned sorting function to an accessor column. Do not sort on rendered Gantt elements.

Resizing uses the standard size, minSize, and maxSize column options; the chart host follows the cell width. There is no graph-specific sizing API in @busmap/table.

The decorative grid and header must use the same interval count: four in this example, five in Bus Map. Keep both at the full chart width without horizontal padding. Do not mix this grid with internal Gantt dividers.

After sorting in both directions, resizing, advancing the live domain and scrolling to newly mounted rows, verify grid boundaries against the header within one pixel. Also verify the actual canvas height, range/point vertical center and date-to-pixel scale. Gantt resize updates are asynchronous; wait for its canvas width and scale to settle before asserting positions. The Bus Map consumer keeps this runnable regression in packages/design-system/scripts/virtualization-browser.test.mjs; it needs a visible or headless Chromium page with local CDP enabled and the dev server at http://127.0.0.1:5173/.

Interactions and accessibility ​

The example treats each Gantt as a static visual summary and exposes the consumer-provided scheduleSummary as its accessible name. @lego/graphs draws its ranges on canvas; the chart does not automatically produce a screen-reader description of each activity.

For clickable graph items, register the additional MouseEvents and MouseEventsSetAction constructors and place the corresponding Gantt mouse-event elements inside the GanttRow. The library emits custom events such as gantt-click; attach and remove a DOM event listener in an effect, then dispatch a consumer action using the event detail. Do not mark an interactive chart aria-hidden or role="img"; provide keyboard-operable controls and an accessible name/description for its interaction.

Retain the table's own accessible label, native sorting controls, and resize separators. Test keyboard navigation and screen-reader output with the graph column in place. A canvas image description does not replace meaningful row and column headers.
