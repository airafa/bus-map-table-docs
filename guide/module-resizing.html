Module resizing and draggable separators ​

Archived

This describes an earlier Flexbox implementation that no longer exists in Bus Map, including the BusDashboardUI.Splitter wrappers it used. Use the module resizing package guide instead.

This guide explains the Bus Map implementation and how to add the same behavior to another Lego DnD starterkit application on an air-gapped computer.

The implementation described here is from the Bus Map application, not a feature supplied automatically by the original starterkit or by @busmap/table. No new splitter library, DnD library, network service, or npm package is required.

Application integration, not table-column resizing

This guide covers the panels surrounding modules. For resizing columns inside a table, see Column resizing. For placing a table in a feature module, see Starter-kit integration.

Source paths in this guide are relative to the Bus Map application monorepo root: the directory containing its root package.json, app/, modules/, and packages/. These application files are not included in the table documentation repository. The portable code in section 9 is included here so the implementation does not require access to that source.

1. What actually resizes ​

The separator resizes two adjacent layout panels, not the module implementations themselves. Each panel hosts a module, and the module fills the panel.

text
LayoutProvider
  recursive Layout
    dashboard panel: flex-direction: row
      schedule panel: flex: 25 1 0%
        web-module: bus schedule
      separator
      route-map panel: flex: 75 1 0%
        web-module: route map

Dragging the separator changes the panels' style.flex values in the starterkit layout state. React renders the updated values, and the browser recalculates the available sizes.

There are three different drag interactions in this application:

InteractionMechanismResult
Resize module panesPointer Events on LayoutSeparatorChanges adjacent layout flex weights
Insert layouts/modules in editor modeStarterkit HTML drag/drop and palette/tree actionsChanges layout structure or module placement
Resize table columnsShared table packageChanges adjacent table-column widths

This guide covers the first interaction and its integration with the second. Table-column resizing is separate; copying the table package is not required for module-pane resizing.

3. Layout configuration and module placement ​

3.1 Resize configuration belongs on the parent ​

The dashboard's relevant configuration is:

json
{
  "uuid": "bus-dashboard",
  "name": "layout",
  "style": {
    "display": "flex",
    "flexDirection": "row",
    "flex": 1
  },
  "droppable": false,
  "layoutElementType": "LAYOUT",
  "resizable": {
    "minPercent": 25,
    "maxPercent": 75
  },
  "items": [
    {
      "uuid": "schedule-pane",
      "name": "schedule",
      "style": {
        "display": "flex",
        "flexDirection": "column",
        "flex": "25 1 0%"
      },
      "droppable": true,
      "onlyDropInside": true,
      "layoutElementType": "LAYOUT"
    },
    {
      "uuid": "route-map-pane",
      "name": "route-map",
      "style": {
        "display": "flex",
        "flexDirection": "column",
        "flex": "75 1 0%"
      },
      "droppable": true,
      "onlyDropInside": true,
      "layoutElementType": "LAYOUT"
    }
  ]
}

Important details:

  • resizable belongs to the panel containing the adjacent panes.
  • Its items should be layout panels, each wrapping its module.
  • Child style.flex values define relative sizes, not fixed pixel widths.
  • The parent direction determines the resize axis; child direction controls content inside each pane.
  • droppable controls editor insertion, not whether resizing works.
  • onlyDropInside restricts the panel's canvas drop behavior. It does not impose resize limits.
  • Percent limits apply to the first pane's share of each adjacent pair. They are not percentages of the entire application when there are more than two panes.

For the current two-pane dashboard, the starting split is 25:75 and the allowed first-pane share is 25% through 75%.

The renderer does not clamp the initial configuration at mount time. Configure initial weights within the intended limits.

3.2 Put modules inside the wrapper panels ​

The module configuration uses UUID paths:

json
{
  "module-bus-schedule": {
    "module": "module-bus-schedule",
    "container": ["bus-dashboard", "schedule-pane"],
    "init": true,
    "editable": true
  },
  "module-route-map": {
    "module": "module-route-map",
    "container": ["bus-dashboard", "route-map-pane"],
    "init": true,
    "editable": true
  }
}

Replace these module names with modules already registered in the destination site.

An array container targets a node in the recursive layout tree. A string container targets the separate named-panel registry. Both are supported by the starterkit, but the separator is inserted between layout.items, not between arbitrary modules appended from the named-panel registry.

Do not place two raw MODULE items directly under a resizable parent and expect this implementation to resize them. It reads item.style and finds panel DOM nodes through data-layout-id; module styling is passed through config.style, and web-module does not expose that panel marker.

4. Rendering and state updates ​

4.1 The recursive renderer inserts separators ​

For each layout panel, the renderer:

  1. Calculates childPath = [...path, layout.uuid].
  2. Iterates through layout.items.
  3. Inserts a separator before every item except the first when layout.resizable exists.
  4. Gives the separator the parent, previous item, current item, and parent path.
  5. Recursively renders the current item.

For three panes the DOM becomes:

text
parent panel
  panel A
  separator A/B
  panel B
  separator B/C
  panel C

Fragment groups the separator and pane in React without adding a DOM wrapper. That matters: both pane elements must remain direct flex children of the parent.

Separators are presentation elements, not layout nodes. They do not receive layout UUIDs or appear as entries in the Elements tree.

4.2 Panel identity is required ​

Panel.jsx renders:

jsx
data-layout-id={uuid}

On pointer down, the separator searches its parent's direct DOM children for the two panel UUIDs. It measures those panels using getBoundingClientRect().

Do not identify adjacent panes with previousSibling or array indexes. Separators and other DOM nodes can appear between panes; stable UUIDs are the intended identity.

4.3 Paths include the root UUID ​

For the schedule pane:

text
["bus-dashboard", "schedule-pane"]

For a nested pane:

text
["root-uuid", "group-uuid", "pane-uuid"]

The separator receives the path to the parent and appends the affected pane UUID.

updateLayout resolves the parent by skipping the root UUID and then finds the child by the final UUID. findLayoutItem itself starts at the supplied node and traverses its children; callers must use the appropriate root-relative path convention.

4.4 State is authoritative ​

The resize sequence is:

text
Pointer move or key press
  -> clamp percentage
  -> updateLayout(before path, updated before panel)
  -> updateLayout(after path, updated after panel)
  -> wildcard layout notifications
  -> LayoutProvider creates a new context value
  -> Layout renders updated styles
  -> browser recalculates flex sizes

Both updates preserve the existing node fields and merge the existing style:

jsx
{
  ...before,
  style: {
    ...before.style,
    flex: "40 1 0%"
  }
}

Preserving style fields avoids deleting display, flexDirection, padding, or other editor settings.

The current state service updates the pair with two calls, not an atomic transaction. Its non-root update implementation emits an element-type add notification plus the wildcard notification; consumers should not assume it always emits UPDATE_LAYOUT.

Do not replace state updates with element.style.width = .... Direct DOM changes would leave the editor model and later renders out of sync.

5. Resize mathematics ​

5.1 Read the existing weights ​

The implementation reads the first numeric value of each flex shorthand:

js
const beforeWeight = Number.parseFloat(before.style?.flex) || 1;
const afterWeight = Number.parseFloat(after.style?.flex) || 1;
const totalWeight = beforeWeight + afterWeight;
const percent = beforeWeight / totalWeight * 100;

For "25 1 0%" and "75 1 0%":

text
totalWeight = 100
percent = 25

For "2 1 0%" and "3 1 0%":

text
totalWeight = 5
percent = 40

5.2 Convert pointer movement to a percentage ​

At pointer down, the separator records:

  • Initial clientX or clientY.
  • Combined measured pane width or height.
  • Initial first-pane percentage.

For each move:

text
delta = current coordinate - starting coordinate
directionSign = reverse flex direction ? -1 : 1
requestedPercent = startingPercent + delta / combinedPaneSize * 100 * directionSign
nextPercent = min(maxPercent, max(minPercent, requestedPercent))

The measured size is the sum of the two panes, excluding the separator. It is not the whole parent width, which would produce incorrect sensitivity with multiple siblings.

Example:

text
Pane widths: 250px + 750px = 1000px
Starting share: 25%
Pointer movement to the right: 100px
New share: 25 + 100 / 1000 * 100 = 35%

5.3 Redistribute without changing the pair total ​

text
newBeforeWeight = nextPercent / 100 * totalWeight
newAfterWeight = (100 - nextPercent) / 100 * totalWeight

The written styles are:

text
before.flex = "<newBeforeWeight> 1 0%"
after.flex  = "<newAfterWeight> 1 0%"

If existing weights are 2 and 3, moving to 60% produces 3 and 2, not 60 and 40.

This preserves the pair's combined allocation relative to a third sibling. Replacing every pair with weights summing to 100 would distort layouts whose other weights use a different scale.

The 0% basis makes flex growth determine the split. Fixed widths, intrinsic minimum sizes, margins, or unequal padding can prevent the visible pixel split from exactly matching the weight ratio.

6. Pointer, keyboard, and accessibility behavior ​

6.1 Pointer lifecycle ​

EventBehavior
pointerdownAccepts primary-button input, measures panes, snapshots starting values, captures pointer
pointermoveCalculates movement from the snapshot and updates both weights
pointerupClears active drag state
pointercancelClears active drag state
lostpointercaptureClears active drag state

useRef stores the drag snapshot without triggering a render for every snapshot change.

setPointerCapture(pointerId) keeps pointer events directed to the separator when the pointer leaves its narrow hit area. The browser normally releases capture on pointer up or cancel.

touch-action: none prevents touch scrolling from taking over the resize gesture. This implementation uses React event handlers and pointer capture rather than installing document-level move listeners.

6.2 Orientation ​

Parent flexDirectionMeasured sizeCoordinateSeparator aria-orientation
rowWidthclientXvertical
row-reverseWidthclientX, inverted deltavertical
columnHeightclientYhorizontal
column-reverseHeightclientY, inverted deltahorizontal

Separator orientation describes the line itself. A vertical line moves left/right; a horizontal line moves up/down.

The current implementation detects direction from parent.style.flexDirection, not computed CSS. Keep that value explicit in the layout configuration.

6.3 Keyboard behavior ​

Layout directionKeys
RowLeft/Right
ColumnUp/Down
EitherHome sets the first pane to minPercent; End sets it to maxPercent

Arrow keys change the first pane's share by 2 percentage points, with the sign inverted for reverse directions.

There is no Shift acceleration for module-pane separators. The table-column separators have different keyboard rules.

The separator has role="separator", tabIndex={0}, an accessible pair-specific label, aria-orientation, and numeric aria-valuemin, aria-valuemax, and rounded aria-valuenow. aria-valuenow describes the first pane's pair share, not its pixel width.

Keep visible keyboard focus styling when adapting the presentation.

7. CSS and module content ​

7.1 Containers must be allowed to shrink ​

The important layout rules are:

css
.pane {
  display: flex;
  min-width: 0;
  min-height: 0;
  box-sizing: border-box;
  overflow: hidden;
}

.moduleHost {
  display: flex;
  flex: 1;
  flex-direction: column;
  min-width: 0;
  min-height: 0;
}

Flex children otherwise retain automatic minimum sizes based on their contents. A wide table or canvas can then stop its pane shrinking.

The current app also gives its document, root, and module hosts a usable height. A column splitter cannot distribute vertical space correctly if its ancestor chain has no constrained height.

Scroll inside the content that needs scrolling. For example, a schedule table can overflow horizontally inside a narrow pane without forcing the entire dashboard wider.

7.2 Separator appearance is independent of its logic ​

The current design system supplies:

  • A fixed, non-growing flex basis for the hit area.
  • A centered grip.
  • col-resize or row-resize.
  • touch-action: none.
  • Hover and keyboard-focus outlines.
  • Theme tokens for sizes and colors.

You can use ordinary div and span elements with local CSS instead. Copying Bus Map's entire design system is unnecessary.

7.3 Content must respond to its container ​

The layout service does not call a generic module.resize() method or recreate modules during dragging. Stable React keys and module UUIDs keep existing hosts in place.

DOM content usually reflows automatically. Canvas, chart, map, and virtualized widgets may need their existing container-resize support:

  • The shared table's packages/table/src/ResizableTable.tsx uses ResizeObserver for element measurements.
  • The schedule's modules/module-bus-schedule/src/components/BusSchedule.tsx observes row height.
  • The route map's modules/module-route-map/src/components/RouteMap.tsx calls OpenLayers updateSize() before fitting routes. Check that the destination map wrapper also handles container resizing; do not assume every package version does.

If a destination widget lacks this behavior, observe its actual host and invoke that widget's documented resize method. Disconnect the observer during the widget's normal unmount/destroy lifecycle. Listening only to window.resize is insufficient because dragging a pane does not resize the browser window.

8. Editor mode, DnD, and persistence ​

8.1 Resizing and editing share one model ​

The Properties sidebar edits style.flex and style.flexDirection on the same layout nodes the separator updates.

Consequently:

  • A separator reads user-edited flex weights on subsequent renders.
  • Turning editor mode off does not restore the original split.
  • Nested layouts inserted by DnD participate in the same recursive renderer.
  • An inserted group is not automatically resizable: it needs its own resizable configuration.
  • If DnD places a raw module directly into a resizable parent's items, the panel-only resize precondition is broken. Use wrapper panels as drop targets.

In Bus Map, editor insertion and selection are development-only, but pane resizing remains available in production. The separator is not gated by devMode.

The separator itself does not use draggable, HTML DataTransfer, getTransferData, or Baseplate module creation. Do not mark the separator draggable; native drag/drop can interfere with pointer resizing.

8.2 Current persistence behavior ​

Layout changes are in memory only. There is no implemented layout storage, export/import, or backend persistence service.

  • React rerenders preserve the state.
  • Editor-mode toggles preserve it.
  • A full reload initializes from configuration again.
  • The localization initialization also calls addLayout([], general.layout) when localization changes, so do not promise that runtime language changes preserve an edited layout.

This is separate from theme persistence.

If persistence is required in the destination application, design it explicitly around serializable layout data and Baseplate module initialization. Validate saved nodes, UUIDs, directions, positive flex weights, and resize limits before restoration. Avoid serializing live module instances or appending duplicate modules during startup.

9. Porting to another starterkit application ​

9.1 Keep the destination's architecture and versions ​

The original sibling starterkit uses @starterkit/layout; Bus Map uses @busmap/layout. Substitute the destination's existing workspace scope, not necessarily either of these names.

Do not perform a workspace-wide rename or framework upgrade just to add resizing.

Minimum changes:

Destination fileChange
packages/types/src/Layout.tsAdd optional resize configuration
app/src/components/Layout/Layout.jsxAdd separator and insert it between panel items
app/src/components/Layout/Panel.jsxAdd data-layout-id to the actual panel DOM element
Local layout stylesheetAdd separator and shrinkable-container styles
app/static/configs/general.jsonConfigure a resizable parent and child weights
app/static/configs/modules.jsonPlace destination modules inside those panels

Keep the existing layout provider and updateLayout service. The original starterkit already has the child-panel update path needed here. Bus Map's additional root-node update support is not required to resize child panes.

9.2 Add the type ​

Inside the destination LayoutElementType:

ts
resizable?: {
  minPercent: number;
  maxPercent: number;
};

For new React layout-style declarations, React.CSSProperties is the appropriate type for objects such as { flex: 1 }; CSSStyleDeclaration describes a browser style object. The older starterkit uses the latter in this contract. Do not copy all of Bus Map's type changes blindly; address destination typecheck errors using its existing React style conventions.

9.3 Expose panel identity ​

In the destination Panel.jsx, add the marker to its outer DOM element. Preserve its ref, handlers, styles, classes, children, and module rendering:

jsx
<div
  ref={refPanel}
  className={panelClassName}
  data-layout-id={uuid}
  {...rest}
  {...dropProps}
  onClick={handlePanelClick}
>
  {children}
  {/* Keep the existing module rendering here. */}
</div>

If the panel uses a styled wrapper, verify it forwards data-* attributes and the ref to the actual DOM node.

9.4 Add the separator component ​

The following portable JSX uses ordinary DOM elements instead of Bus Map's design-system wrappers. It uses the same algorithm, with explicit reporting if the destination layout service cannot find a pane.

Place it in the existing Layout.jsx, above Layout. Merge its imports with the file's existing imports:

jsx
import React, { Fragment, useRef } from "react";
import { useLayoutContext, updateLayout } from "@starterkit/layout";
import "./LayoutResize.css";

function LayoutSeparator({ parent, before, after, path }) {
  const drag = useRef(null);
  const vertical = parent.style?.flexDirection?.startsWith("column");
  const reverse = parent.style?.flexDirection?.endsWith("reverse");
  const min = parent.resizable.minPercent;
  const max = parent.resizable.maxPercent;
  const beforeWeight = Number.parseFloat(before.style?.flex) || 1;
  const afterWeight = Number.parseFloat(after.style?.flex) || 1;
  const totalWeight = beforeWeight + afterWeight;
  const percent = beforeWeight / totalWeight * 100;

  const resize = (value) => {
    const next = Math.min(max, Math.max(min, value));
    const beforeResult = updateLayout([...path, before.uuid], {
      ...before,
      style: {
        ...before.style,
        flex: `${next / 100 * totalWeight} 1 0%`,
      },
    });
    if (beforeResult === false) {
      throw new Error(`Cannot resize layout panel: ${before.uuid}`);
    }
    const afterResult = updateLayout([...path, after.uuid], {
      ...after,
      style: {
        ...after.style,
        flex: `${(100 - next) / 100 * totalWeight} 1 0%`,
      },
    });
    if (afterResult === false) {
      throw new Error(`Cannot resize layout panel: ${after.uuid}`);
    }
  };

  return (
    <div
      className="layout-splitter"
      role="separator"
      aria-label={`Resize ${before.name} and ${after.name} panels`}
      aria-orientation={vertical ? "horizontal" : "vertical"}
      aria-valuemin={min}
      aria-valuemax={max}
      aria-valuenow={Math.round(percent)}
      tabIndex={0}
      onPointerDown={(event) => {
        if (event.button !== 0) return;
        const siblings = [...event.currentTarget.parentElement.children];
        const first = siblings.find(
          node => node.dataset.layoutId === before.uuid
        );
        const second = siblings.find(
          node => node.dataset.layoutId === after.uuid
        );
        if (!first || !second) {
          throw new Error("Resizable layout panels are missing");
        }
        const axis = vertical ? "height" : "width";
        drag.current = {
          start: vertical ? event.clientY : event.clientX,
          size:
            first.getBoundingClientRect()[axis] +
            second.getBoundingClientRect()[axis],
          percent,
        };
        event.currentTarget.setPointerCapture(event.pointerId);
      }}
      onPointerMove={(event) => {
        if (!drag.current || drag.current.size === 0) return;
        const coordinate = vertical ? event.clientY : event.clientX;
        const delta = coordinate - drag.current.start;
        resize(
          drag.current.percent +
          delta / drag.current.size * 100 * (reverse ? -1 : 1)
        );
      }}
      onPointerUp={() => { drag.current = null; }}
      onPointerCancel={() => { drag.current = null; }}
      onLostPointerCapture={() => { drag.current = null; }}
      onKeyDown={(event) => {
        const decrease = vertical ? "ArrowUp" : "ArrowLeft";
        const increase = vertical ? "ArrowDown" : "ArrowRight";
        if (event.key === decrease || event.key === increase) {
          event.preventDefault();
          resize(
            percent +
            (event.key === increase ? 2 : -2) * (reverse ? -1 : 1)
          );
        } else if (event.key === "Home" || event.key === "End") {
          event.preventDefault();
          resize(event.key === "Home" ? min : max);
        }
      }}
    >
      <span className="layout-splitter-handle" />
    </div>
  );
}

The === false checks are deliberate: the original service returns false on failed lookup but normally returns undefined after a successful child update. A truthiness check would incorrectly treat success as failure.

This is not transactional: if the second update fails after the first succeeds, the first is already applied. Treat that error as a broken tree/path contract, not a normal resize outcome.

9.5 Change only child rendering ​

Keep the destination's array handling, MODULE branch, Panel props, classes, and callbacks. In the layout-panel branch, calculate:

jsx
const childPath = [...path, layout.uuid];

Replace the old recursive rendering of the entire layout.items array inside Panel with:

jsx
{layout.items?.map((item, index) => (
  <Fragment key={item.uuid}>
    {index > 0 && layout.resizable && (
      <LayoutSeparator
        parent={layout}
        before={layout.items[index - 1]}
        after={item}
        path={childPath}
      />
    )}
    <Layout
      path={childPath}
      layout={item}
      onPanelClick={onPanelClick}
      onModuleClick={onModuleClick}
    />
  </Fragment>
))}

Replace the old child block; do not leave both versions in place, or modules will render twice.

Do not add a DOM wrapper around each pair. The Fragment is intentional.

Create LayoutResize.css next to Layout.jsx if the destination does not already have an appropriate stylesheet. This portable example uses explicit CSS values so it does not depend on Bus Map's theme tokens. Replace colors with the destination's theme variables where available.

If the site uses CSS Modules, import a local .module.css instead and replace the example class strings with its exported classes.

9.7 Configure, then validate ​

  1. Add the wrapper panels and parent resizable settings to the destination's existing layout, using section 3 as the shape.
  2. Put destination module names under those wrapper-panel UUID paths.
  3. Set display: "flex" and explicit flexDirection on the parent.
  4. Use finite, positive flex-grow weights with 1 0% as the remaining shorthand values.
  5. Require finite limits satisfying 0 < minPercent <= maxPercent < 100.
  6. Start with two panes in row direction; test before adding nesting or reverse directions.
  7. Keep existing DnD/module lifecycle code. No new module registration topic or provider is needed for resizing.

The type and JSON configuration do not perform runtime validation by themselves. If the destination accepts imported or user-supplied layouts, enforce these constraints at that input boundary using its existing validation/error-reporting mechanism.

10. Air-gapped transfer and installation ​

10.1 If the target site already runs offline ​

This is the simplest case:

  1. Transfer this guide and the approved source changes through your organization's approved media/process.
  2. Apply the small changes in section 9 to the existing checkout.
  3. Leave the dependency manifests and lockfile unchanged.
  4. Run the destination's existing typecheck, build, and development commands.

There is no reason to run npm install or fetch a splitter dependency. React, the layout workspace, browser Pointer Events, and CSS already provide the required behavior.

Do not replace the target's working dependency tree with Bus Map's dependency tree. The original starterkit and this application use different framework/toolchain versions.

10.2 If dependencies must be restored offline ​

First use the destination site's own manifests, lockfile, Node version, Yarn version, private package permissions, and any existing approved offline registry or package mirror.

For a Yarn Classic destination without an existing offline mirror, an approved connected staging machine can prepare one:

  1. Use a clean staging copy of the destination repository.

  2. Use the same Node/Yarn versions and platform/architecture as the offline build machine, where practical.

  3. Configure an offline mirror in that staging copy's .yarnrc:

    text
    yarn-offline-mirror "./offline-mirror"

  4. With authorized registry access, restore the destination's locked dependencies:

    bash
    yarn install --frozen-lockfile

  5. Verify the mirror contains all required tarballs. A pre-populated cache can affect mirror preparation; if needed, populate it using an isolated empty cache directory on the staging machine rather than clearing a shared cache.

  6. Transfer the approved source, lockfile, .yarnrc mirror setting, complete mirror, and approved Node/Yarn installers.

  7. On the air-gapped machine, from the destination monorepo root:

    bash
    yarn install --offline --frozen-lockfile

  8. Run the destination's normal validation and build.

An offline mirror is a Yarn Classic mechanism, not a universal package-manager setting. If the destination uses another Yarn generation or package manager, follow its existing offline process instead.

Native dependencies, platform-specific optional packages, Git dependencies, and install scripts that fetch binaries can require additional approved artifacts. Validate a clean install in a genuinely network-disabled staging environment before transfer; tarballs alone are not proof that the build is fully offline.

Do not transfer personal registry credentials, tokens, unrelated user caches, or secrets. Do not assume copying node_modules between operating systems or architectures will work.

10.3 Build-time offline versus runtime offline ​

The separator requires no network at runtime. That does not make the entire destination application offline-ready.

Check maps/tiles, fonts, icons, APIs, telemetry, dynamic assets, and development-server host bindings separately. In particular, Bus Map's normal OpenStreetMap basemap is a network resource; its presence is not required by the resize logic.

Use approved local services/assets for features the target must support without external connectivity.

11. Verification ​

11.1 Small runnable arithmetic check ​

This command needs only Node's standard library. Run it from any directory:

bash
node --input-type=module <<'NODE'
import assert from "node:assert/strict";

function weights(before, after, requested, min = 25, max = 75) {
  const next = Math.min(max, Math.max(min, requested));
  const total = before + after;
  return [next / 100 * total, (100 - next) / 100 * total];
}

function moved(start, delta, size, reverse = false) {
  return start + delta / size * 100 * (reverse ? -1 : 1);
}

assert.deepEqual(weights(25, 75, moved(25, 100, 1000)), [35, 65]);
assert.deepEqual(weights(2, 3, 60), [3, 2]);
assert.deepEqual(weights(2, 3, -100), [1.25, 3.75]);
assert.deepEqual(weights(2, 3, 200), [3.75, 1.25]);
assert.equal(moved(50, 100, 1000, true), 40);
assert.deepEqual(weights(2, 3, 25), [1.25, 3.75]);
assert.deepEqual(weights(2, 3, 75), [3.75, 1.25]);
console.log("Resize arithmetic checks passed");
NODE

This is an explanatory arithmetic check, not a test of the actual JSX, DOM measurement, or application wiring. Complete the interaction checks below as well.

11.3 Interaction acceptance checklist ​

  • [ ] Two panes render with one separator, and modules mount once.
  • [ ] Pointer dragging changes the split immediately without a full reload.
  • [ ] Dragging beyond the ends stops at 25% and 75% for the example configuration.
  • [ ] Starting at 25% with combined pane size 1000px, moving right 100px reaches approximately 35% in an LTR row layout.
  • [ ] Releasing outside the separator stops resizing; later pointer movement does nothing.
  • [ ] Pointer cancellation or lost capture leaves no active drag.
  • [ ] Secondary-button pointer input does not start resizing.
  • [ ] Touch dragging works on the target hardware without page scrolling taking over.
  • [ ] Tab reaches the separator and a focus indicator is visible.
  • [ ] Arrow keys change the first pane by 2 percentage points; Home/End reach limits.
  • [ ] aria-valuenow changes with the weights.
  • [ ] A column layout resizes by height, not width.
  • [ ] Reverse directions invert physical drag/key behavior as described in section 6.
  • [ ] With three panes and weights 2, 3, 5, resizing the first pair to 60% yields 3, 2, 5; the third weight stays 5.
  • [ ] Nested groups update the intended UUID paths, not similarly named panels elsewhere.
  • [ ] Editing Flex in Properties affects the next separator interaction.
  • [ ] Turning editor mode off preserves the split; production still allows resizing.
  • [ ] Existing DnD insertion still works in permitted wrapper-panel drop targets.
  • [ ] Tables/canvases/maps resize their content rather than overflowing or showing stale rendering.
  • [ ] Narrow panes scroll content where intended rather than expanding the whole layout.
  • [ ] Full reload returns to configuration defaults unless persistence was separately implemented.
  • [ ] No resize action generates network requests.

For numerical browser checks, compare flex weights or compute firstSize / (firstSize + secondSize) * 100. Do not divide by the whole parent width, which includes the separator and possibly other panes. Allow subpixel rounding and account for panel padding/borders.

Deliberate scope and ceilings ​

  • Panel wrappers are required. The current renderer does not filter unsupported raw module siblings out of resizable groups.
  • Weights must be positive finite numbers. The source uses parseFloat(...) || 1: missing/non-numeric/zero values become 1; negative values and unusual flex keywords are not a supported sizing contract.
  • Limits are pair percentages, not pixel minimums. A 25% pane can still be unusably small in a tiny window. Add content-specific constraints only if the destination actually needs them.
  • Direction comes from inline configuration. CSS-only direction changes are not detected.
  • RTL is not fully handled. The code compensates for row-reverse/column-reverse, but not an inherited RTL inline direction. Test and deliberately adapt row coordinate/key semantics if the destination uses RTL; do not assume reverse-direction support covers it.
  • No automatic initial normalization. Edited or imported weights outside the configured range are clamped on the next resize interaction, not immediately on render.
  • No atomic pair-update API or frame throttling. Every handled move updates both nodes through the existing service. Profile the real target before adding batching or scheduling.
  • No dedicated simultaneous-pointer arbitration. Drag state does not store a pointer ID; multiple concurrent touches on the same separator are not explicitly coordinated.
  • Stable geometry is assumed during a gesture. The combined pane size is measured at pointer down, not on every move. Changing the viewport, direction, or tree during the same drag is not specially coordinated.
  • No undo, snapping, collapse, double-click reset, or persistence. These are separate features, not hidden capabilities of the starterkit.

For the existing two-pane dashboard, the small combination of recursive layout state, flex weights, Pointer Events, and accessible keyboard handling is sufficient. Port those pieces rather than introducing a second layout engine.
