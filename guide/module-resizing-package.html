Add a module separator ​

This guide helps you add a draggable separator between two parts of an application. It starts with the files and packages you need and ends with a working starterkit integration and a checklist.

You do not need to understand CSS Grid, Redux, or pointer events first. You do need access to the application source, a terminal, and a way to edit files. Ask your team if your project uses different paths or commands.

Two different kinds of resizing

This guide resizes application panes around modules. It uses @busmap/module-resizing, not @busmap/table. For resizing columns inside a table, use Column resizing.

The Flexbox guide and hybrid Grid guide are archived. Their implementation details describe earlier versions. Do not copy their separator code into this package-based implementation.

1. Understand the result ​

Imagine two boxes with a narrow handle between them:

text
Wide screen:   [ first pane ] | [ second pane ]
Narrow screen: [ first pane ]
               --------------
               [ second pane ]

Dragging the handle changes the share of space given to each box. The first pane might use 40% and the second 60%. On a narrow screen, the same percentages control their heights. The handle also supports keyboard and touch input.

A module is an application feature, such as a schedule or map. A panel is a container that holds it. The package resizes two direct children of one panel; it does not move modules between panels.

2. Know what each part does ​

PartResponsibility
Layout JSONTurns resizing on for one parent: resizable, minSplit, maxSplit.
The layout rendererRenders ResizableSplit for that parent when it has exactly two children.
@busmap/module-resizingResizableSplit owns the Grid, the separator, pointer and keyboard input, limits, and its own styles.
A preferences storeOptional. Remembers each user's split and shares it with the editor.

Your existing Panel component does not change.

During a drag, the package previews the change without saving on every pointer movement. It reports the final percentage through onSplitChange when the drag ends, or when a supported keyboard key is pressed.

The resizing package does not contain Redux, the editor, or storage. The package uses React components and native browser APIs; it adds no Web Components.

3. Gather the required materials ​

Obtain these through your team's approved transfer process:

  1. The source checkout containing packages/module-resizing.
  2. Its already installed build dependencies, or an approved local package cache/internal registry containing the versions in its package.json.
  3. The destination starterkit source and its own dependencies.
  4. React 19.3.1 and a compatible React DOM installation. The package declares React 19.3.1 as an exact peer; it does not include React in its tarball.
  5. If you want the same Redux/localStorage behavior as Bus Map, the separate packages/user-preference-datasource source and its dependencies, including Redux Toolkit. This workspace is private and is not included in the resizing tarball.
  6. This documentation, built and transferred as explained at the end of this guide, if the documentation site is hosted internally.

The example commands below use Yarn 1 and npm. They are local programs; do not run an install command if the required dependencies are not already available in the approved local cache or internal registry. A tarball alone does not provide your starterkit, React, map resources, or the preferences adapter. Never transfer registry credentials with the package.

4. Build the resizing package ​

On the machine with the Bus Map application checkout, open a terminal at its workspace root. This is the folder containing app/ and packages/.

First, build the package:

sh
yarn workspace @busmap/module-resizing build

The build checks the TypeScript source and generates JavaScript and type declarations. The destination can use the JavaScript even if its own panel is written in JSX.

5. Check the package ​

Run its tests:

sh
yarn workspace @busmap/module-resizing test

The tests include a tarball and a small TypeScript consumer check. Stop if the build or tests fail; do not transfer an unverified package.

6. Create the transfer file ​

Change to the package folder:

sh
cd packages/module-resizing

Create a package archive:

sh
npm pack

npm pack runs the package's build again. It prints a filename such as busmap-module-resizing-0.1.0.tgz. Use the actual filename it prints. The archive contains built JavaScript, CSS, declarations, and the package README. It does not contain React or the preferences adapter.

7. Transfer and verify the archive ​

Calculate a checksum before transfer:

sh
sha256sum busmap-module-resizing-0.1.0.tgz

Transfer the archive and checksum through the approved process. Run the same checksum command on the destination and compare the results. A checksum detects transfer errors; it does not prove who supplied a file.

8. Install into the destination application ​

From the destination workspace root, use the local archive:

sh
yarn workspace YOUR_APP_WORKSPACE add file:/absolute/path/busmap-module-resizing-0.1.0.tgz

Replace YOUR_APP_WORKSPACE and the path with your actual workspace name and transferred file. Yarn may try to fetch other missing dependencies from its configured registry. Make all dependencies available in the approved local cache or internal registry before running the command, and follow your organization's network restrictions.

Check that the application uses the expected React version and only one compatible React instance. Resolve dependency errors before continuing.

9. Configure the resizable parent ​

Find your application's layout configuration. In Bus Map it is app/static/configs/general.json. Choose one existing parent with exactly two direct pane layouts, and edit only that object; preserve unrelated layouts, modules, and editor options:

json
{
  "uuid": "your-parent-uuid",
  "name": "dashboard",
  "layoutElementType": "LAYOUT",
  "style": { "display": "flex", "flex": 1, "flexShrink": 0, "minHeight": 0 },
  "resizable": true,
  "minSplit": 20,
  "maxSplit": 80,
  "items": [
    { "uuid": "first-pane", "name": "first", "layoutElementType": "LAYOUT" },
    { "uuid": "second-pane", "name": "second", "layoutElementType": "LAYOUT" }
  ]
}
  • resizable, minSplit, and maxSplit are the whole resizing contract. The limits must satisfy 0 < minSplit <= maxSplit < 100; otherwise the component throws when it renders. An optional "initialSplit": 40 sets the starting percentage (default 50). Resizing is read once, when the configuration loads.
  • The style only makes the parent a flex container. Do not add Grid tracks; the component renders its own Grid inside the parent and fills it. Mobile height resizing needs a parent with a constrained height.
  • Use stable, unique UUIDs. Saved splits are stored under the parent's UUID.
  • Keep each module's existing placement. In Bus Map, modules point at a pane through a UUID path in app/static/configs/modules.json, for example "container": ["your-parent-uuid", "first-pane"]. Follow your application's own convention if it differs.

10. Render the split ​

Find the recursive layout renderer. In Bus Map it is app/src/components/Layout/Layout.jsx. Where it renders a layout item's direct content (child layouts plus assigned modules) inside its Panel, add one condition:

jsx
import { ResizableSplit } from "@busmap/module-resizing";

<Panel {...existingPanelProps}>
  {layout.resizable === true && content.length === 2
    ? <ResizableSplit leftContent={content[0]} rightContent={content[1]}
        min={layout.minSplit} max={layout.maxSplit} initialSplit={layout.initialSplit}
        separatorLabel={`Resize ${layout.name} panels`} />
    : content}
</Panel>

That is the complete integration. There is no stylesheet to import, no hook to call, and no change to Panel: it stays a plain container with its own editor click and drag-and-drop handlers. Panels that are not resizable, or do not have exactly two children, render their content as before with no resizing component in the tree, so no child is ever hidden. The divider stops its own click and pointer events, so they do not reach the panel.

Without the next step, the split works but resets to initialSplit on reload.

11. Optional: remember each user's split ​

ResizableSplit keeps its value in local state and reports each completed change through onSplitChange. To persist it, store that value and pass it back as initialSplit; a value that arrives later (such as one loaded asynchronously) replaces the current split.

Bus Map uses the separate packages/user-preference-datasource package, a plain key-to-JSON store with a shared Redux store. It is private, source-based, and not included in the resizing tarball. To use it:

  1. Transfer it into the destination workspace and add "@busmap/user-preference-datasource": "0.0.0" (or its actual version) to the application's dependencies. Make its Redux Toolkit and React dependencies available locally. If the destination does not use workspaces, build or adapt the package separately.

  2. Add "userPreferences": { "url": null } to the general configuration. url: null uses browser localStorage; a URL switches to the remote API mode described in that package's README.

  3. Initialize it once, after the configuration loads and before React mounts. In Bus Map this is in app/src/index.init.ts:

    ts
    import { initializeUserPreferences } from "@busmap/user-preference-datasource";

initializeUserPreferences(general.userPreferences ?? { url: null });

  4. Replace the ResizableSplit from step 10 with a small component that reads and saves the value under the parent's UUID. A component is needed so that only resizable panels subscribe to the store:

    jsx
    import { useUserPreference } from "@busmap/user-preference-datasource";

function SavedSplit({ layout, content }) {
  const { value, save } = useUserPreference(layout.uuid);
  return (
    <ResizableSplit leftContent={content[0]} rightContent={content[1]}
      initialSplit={value?.splitPercent ?? layout.initialSplit}
      min={layout.minSplit} max={layout.maxSplit}
      onSplitChange={splitPercent => save({ splitPercent })}
      separatorLabel={`Resize ${layout.name} panels`} />
  );
}

The store does not validate what it returns; ResizableSplit clamps the value to the limits and ignores non-numeric values. The adapter logs storage errors to the console and shows no notification. If your application already has an equivalent store, use it instead.

12. Optional: edit the split in the properties editor ​

If the properties editor should show the split, read and save the same UUID and { splitPercent } shape through the same store, and use minSplit/maxSplit as the input's limits. In Bus Map this is modules/module-element-properties/src/components/LayoutProperties.tsx:

tsx
const { value, save } = useUserPreference<{ splitPercent: number }>(uuid);
const splitPercent = value?.splitPercent ?? initialSplit;
// On a valid blur: save({ splitPercent: input.valueAsNumber });

An editor save reaches ResizableSplit as a new initialSplit and moves the divider. Do not update the layout tree during drags; the component previews drags internally and commits once.

13. Run the application locally ​

Start the destination using its existing development command. In the Bus Map workspace, that command is:

sh
yarn dev

Open the local address printed by the command. Other features, such as map tiles, may have their own network or local-data requirements.

14. Test mouse, keyboard, and touch ​

  1. Confirm that the two expected modules are visible.
  2. Drag the divider to each limit. It must stop at the configured percentages.
  3. Focus the divider with Tab. On a wide screen, use Left and Right.
  4. Press Home and End to select the minimum and maximum.
  5. Narrow the viewport below 840 CSS pixels. The panes should stack and the divider should remain visible. Use Up and Down to resize.
  6. Test touch dragging on actual touch hardware if available, including dragging outside the visible 12px track and releasing or cancelling.
  7. Test a right-to-left layout: horizontal pointer and arrow directions reverse; vertical directions do not.

The package uses one saved percentage for both orientations. Grid layout and heavy child components still require work, so a particular frame rate is not guaranteed.

15. Test persistence and editor behavior ​

Steps 2–4 apply only if you added step 11 or 12.

  1. Check a panel without resizable and a panel without exactly two children: neither should show a divider.
  2. Drag the divider, reload the same application origin, and confirm that the saved split returns.
  3. Open the editor properties for the parent and confirm the same percentage.
  4. Change the split in the editor and confirm the divider updates.
  5. Confirm that ordinary editor drag-and-drop still works.
  6. Inspect the browser console if the value does not persist. Browser storage may be disabled or full; the adapter logs errors and keeps the latest value visible in memory.

Browser storage is scoped to an origin. Different hostnames or ports have different saved preferences. Clearing site data removes local preferences.

16. Troubleshooting ​

SymptomCheck
No divider"resizable": true (a boolean), exactly two direct children (layouts plus assigned modules), and the gate in the layout renderer.
Error "ResizableSplit requires 0 < min <= max < 100"minSplit and maxSplit are present, numeric, and ordered.
Unexpected starting splitinitialSplit, the configured limits, the UUID, and any existing local preference.
Divider unstyledThe bundler must support CSS imported from dependencies; the package imports its own stylesheet.
Mobile panes do not resizeViewport width and a constrained parent height.
Editor DnD stopped workingPanel keeps its own handlers; nothing should replace the Panel around the split.
Editor shows a different valueBoth editor and layout use the same UUID, the same { splitPercent } shape, and the same preference adapter.
Preferences reseturl: null, initialization before mount, storage access, browser origin, and console errors.
Installation failsExact React peer and all destination dependencies must already be in the local cache or internal registry.

17. Host this documentation internally ​

The documentation source is a separate repository from the application. With its Node.js and VitePress dependencies already installed or available through an approved local cache, run from that repository root:

sh
npm run docs:build

Transfer the generated docs/.vitepress/dist directory through the approved process. Serve it with an internal static HTTP server under /bus-map-table-docs/, matching the configured VitePress base path. Opening index.html directly as a file:// URL is not the supported deployment. Local search is built into the site. Existing links elsewhere in the site may point to external services; they will not work without access to those services.
